# Upgrade Script — client-intelligence 1.x → 2.0.0

**MAJOR-version migration (required reading before completing the upgrade).** The 2.0 model:
private clients live in each member's own My Drive (owner-applied sharing — the 1.x per-instance
ACL model was broken for non-admins, finding F12); org-public clients live in the commons under
uniform all@ writer access; every client has a universal-floor pointer in `public-index/`.

## ⚠ THE ORDERING RULE (data-exposure control)

**Do NOT apply (or let install-collection Step 5.5 apply) the `instances/` all@ WRITER grant
until the gated-instance review below is complete.** 1.x instances may carry per-instance gating
(inherit:false ACLs); the 2.0 uniform grant would expose previously-gated data to the whole org.
upgrade-collection Step 6.5 will flag provisioning on this upgrade — run THIS script's admin half
first, then `@ai:install-collection client-intelligence`.

## Admin half (run before provisioning)

1. **Inventory:** `aifs_list("/shared/client-intelligence/instances/")` → for each instance
   folder, `aifs_get_permissions`. Classify:
   - **Open** — no per-instance ACL beyond inherited org access → becomes org-public in place.
   - **Gated** — carries narrower per-instance grants (inherit:false or explicit member grants
     beyond the org baseline) → FLAGGED; do not proceed past step 3 until each is resolved.
2. **Rebuild the pointer index:** for each instance, overwrite
   `public-index/instances/{slug}.json` with the 2.0 pointer schema: `type: "client"`, name/slug/
   template fields from the 1.x entry + instance.json, `owner`/`owner_hash` = 1.x `created_by`,
   `status` carried over, `scope: "org_public"`, `location: {"path": ".../instances/{slug}/"}`,
   `owner_departed: false`. (Gated instances: write the pointer with `scope: "private"` and a
   `"migration": "pending-owner-decision"` marker instead.)
3. **Resolve every gated instance with its owner** (creator from `created_by`):
   - Owner keeps it gated → the OWNER runs `@ai:transition-client {slug}` after their 2.0 update
     (it copies the instance into their My Drive, flips the pointer to the private tier, and the
     admin then overwrites the /shared original to the archived stub). The 1.x per-instance ACLs
     on the stub become irrelevant.
   - Owner opens it up → admin updates the pointer `scope: "org_public"`, clears the migration
     marker; the 1.x narrow ACLs may be left (harmless under uniform writer) or removed via the
     helper for hygiene.
   - Owner departed/unreachable → admin decides as data custodian; default to gated-preserved
     (treat as "keeps it gated", admin performs the transition copy into an admin-owned private
     client or an org decision is made).
4. **Retire the ACL policy file:** overwrite `config/default-permissions.json` with
   `{"retired": "2.0.0"}`.
5. **Provision:** `@ai:install-collection client-intelligence` — the upgrade interview records
   `clients_default_visibility` (replacing `default_permission_policy_preset`; suggested mapping:
   `closed`→`private_first`, `open`→`org_public_first`, `admin-only`→`private_first`), and
   Step 5.5 applies `collaborative-acls.json` (including the now-safe instances/ grant).

## Member half (surfaced during members' @ai:update of the 2.0 entry)

- Nothing mandatory. Members whose 1.x instances were gated and who chose keep-gated run
  `@ai:transition-client {slug}` once (requires their My Drive space — core 3.9.0+, automatic).
- New verbs to know: tiers, transition-client, owner-run grant/revoke. `@ai:client-intelligence-tutorial`
  covers the model.

## Verification (admin, after both halves)

- Every instance folder has a 2.0 pointer; no pointer carries `"migration": "pending-owner-decision"`.
- `aifs_get_permissions("/shared/client-intelligence/instances/")` shows the all@ writer grant.
- A non-admin member can: create a private client, create an org-public client, edit an
  org-public client (test plan 09 Phase CI).
